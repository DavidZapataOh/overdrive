# Sources

What a researcher is told to read first, and how to take a competitor or reference apart.

## Order

1. The owner's own pages: documentation, pricing, changelog, release notes, status and security pages.
2. The owner's repository: README, source, issues, pull requests, tags (`path:line` when quoting code).
3. Specifications, standards and filings.
4. Independent measurements and write-ups that show their method.
5. Posts, answers and forums: leads to a primary source, never the evidence.

## Taking a competitor or reference apart

One researcher per candidate, the same questions for each:

- What does it offer, with the plan or version each claim applies to, from its pricing and docs pages.
- What changed recently: the last releases or changelog entries.
- How is it built, when it is open: the directory layout, the module that does the thing asked, its tests.
- What do its users complain about: the most discussed open issues, labeled as user reports.

Compare only after all report: the same criteria in the same order for every candidate.
