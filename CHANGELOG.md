# Changelog

## 0.2.0 — 2026-11-12

Lighter critical lane, measured on real tasks: the separate builder and the opus reviews made up most of the critical lane's time and cost without catching more defects.

- Critical tasks are built in the main session; `overdrive:builder` is dispatched only for parallel independent tasks or when the context nears its limit.
- One `overdrive:critical-reviewer` per task, on `sonnet` by default and on `opus` when the task's items include money, data-migration, tenant-isolation or secrets. One inline correction (`Task N: fixing round 1`) and one re-review of only that correction; what is left becomes a ruling or a question to the user.
- `overdrive:final-reviewer` runs only for slices with two or more critical tasks, with the same model rule.
- Reviewers report only findings with a concrete failure mode.
- Agents and CI runs are awaited inside the turn; a turn never ends waiting for one.
- `untested-change` is a `standard` item: a source change with no test is ordinary work, not a domain risk.

## 0.1.2 — 2026-11-12

- Critical lane: the PreToolUse guard now classifies every `git commit` and denies one whose content has a critical domain item (a floor or project-map item; `untested-change`, the other computed items and `risk-map` do not gate) unless the critical flow is under way. The content is the index, the tracked changes for `-a` and pathspec operands, or the whole working tree when another command runs first in the same command line or the commit selects content itself (`-p`, `--interactive`, `--include`, `--pathspec-from-file`); an unborn HEAD is read against the empty tree. The flow is under way when the dispatched `overdrive:builder` commits (the hook input's `agent_type`, exactly `overdrive:builder`), when the active ledger of the current branch (any branch while a merge or squash is being concluded) holds a task marked critical and its run is open (`overdrive ledger critical-flow [--any-branch]`), or when the commit message cites `(lowered by user, D-NNNN)` for an active decision that lowers a lane and is the user's own words or already committed. The deny text lists the steps: plan, `ledger init`, `brief`, `overdrive:builder`, critical review. A request that pre-approves the plan now reads, in `risk-triage`, `risk-scaled-execution` and `decision-planning`, as approval of the plan's content and not of skipping the lane. Only `git commit` calls pay for a classification; a classifier that cannot run lets the commit through. Known limits are listed in docs/guard.md.
- Commit gate refinements: computed domain items (a deploy script, unscanned content) gate; earlier `git add`/`git stage`/`git rm` in the same command line are replayed on a scratch index and read-only commands before the commit are ignored, so staging named paths is not blamed for unrelated work in progress; the deny text names the files; a lowering must use the template wording and its Scope must cover those files; a merge conclusion in a linked worktree finds the main worktree's ledger and Windows git paths are handled as absolute.
- `overdrive ledger critical-flow`: exits 0 when the ledger applies to the current branch, its run is open and a task is marked critical.
- `untested-change` also treats a source as covered when a test the change carries imports it, directly or through one intermediate module, by import syntax only (a route file reached by an endpoint test, a module reached through a shared test helper; mocks, comments and file reads do not count). `overdrive risk --diff` also accepts a range of trees when there is no commit yet. The import lines are read from the files as the change leaves them, so `--diff`, `--staged` and `--worktree` agree.
- Risk-map proposals: lint, formatter, type-check and task-runner configuration is not a floor, rules need evidence in the repository, and a proposal never classifies the request that prompted it.
- The Stop hook and the guard share the code that reads a decision of the user (`lib/lowering.sh`).

## 0.1.1 — 2026-11-11

- The PreToolUse guard approves what the session router needs without a permission prompt: the read-only CLI commands (`risk`, `decisions next-id`, `decisions check`, `recall`) when run through a variable (`R`, `ROOT`, `OD_ROOT` or `PLUGIN_ROOT`) set to the plugin root (`R=<root>; $R/bin/overdrive risk ...`), and `Read` of files inside the plugin directory. A path with a `.` or `..` segment, a symbolic link that resolves outside it and any other value or variable name are not approved. A quoting is accepted only when the root can be written that way as one literal word, which also closes a way for a root containing a quote to turn arguments into part of the path in the existing absolute-path allow. The guard now also matches `Read`; an unrelated call still uses shell builtins only.

## 0.1.0 — 2026-11-11

First release. Overdrive scales process to the risk of each change: a deterministic classifier (`overdrive risk`) puts every change in the `direct`, `standard` or `critical` lane, and each lane brings only the planning, review and evidence it needs. The release ships 14 skills, five subagents (builder, reviewer, critical-reviewer, final-reviewer, researcher), a SessionStart router, a PreToolUse guard, a Stop check for the Risk line and the `overdrive` CLI (risk, brief, review-package, findings, ledger, evidence, pin, overlap, decisions, recall). In the critical lane the guard now holds the final review and the pull request until every critical task has been reviewed after its last change. Marketplace and plugin manifests are included.

- Critical lane: the PreToolUse guard denies dispatching `overdrive:final-reviewer` and `gh pr create` / `gh pr merge`, and `overdrive review-package --require-green` refuses, while a task the ledger marks critical (`Task N: in-progress critical`) has no critical review after its last change. The review is recorded by the guard itself (`Task N: reviewed by critical-reviewer`) when `overdrive:critical-reviewer` is dispatched with `Task N` in its description (or prompt, or a `task-N` brief path); a `reviewing` line the controller writes is a state only, an `overdrive:builder` dispatch is recorded as `Task N: changed by builder` and needs a new review, and `ledger add` refuses the guard's record. A ledger binds to the run's branch (at `ledger init` on a non-default branch, else at the first `ledger add` made on one) and gates only there; a critical task stays gated after `complete` until a review follows its last change. `overdrive brief` marks a critical task in the ledger itself, `Run: closed — <reason>` frees other branches (the run's own branch stays gated), and `overdrive ledger unreviewed [--all-started] [--any-branch]` lists the tasks.
- `risk-triage`: classifies every repository change before its first edit and again on the diff, raises lanes the classifier cannot see, lets only the user lower a floor after hearing the risk (recorded as a decision), and proposes a project risk map once. The session router names the CLI by its absolute path and loads this skill for every change.
- Briefs and review packages carry an `Overdrive CLI:` line with the CLI's absolute path for agents.
- `overdrive risk` works when `TMPDIR` is not writable, falling back to `/tmp` and then the repository's run directory.
- The Stop hook asks for a Risk line only when the turn actually changed a repository.
- Marketplace and plugin manifests.
- `skill-evaluation`: user-invoked workflow for writing a skill test first (pressure baseline, eval suite, skill, pressure again, measurement), with `new-pressure-case` and `split-trigger-set` scripts.
- `deep-research`: user-invoked research workflow that splits a question across `overdrive:researcher` agents with neutral briefs, caps each researcher, labels patterns, gaps and bets, and writes a sourced report file.
- `overdrive brief --text TEXT --neutral [--rules TEXT|-] [--cap N] [--stdout]`: a research brief with the task, rules, cap and report contract only, written under `${TMPDIR:-/tmp}/overdrive-briefs/` or printed with `--stdout`; `deep-research` uses it for comparisons.
- Reviewer agents write findings to the file the prompt or brief names, defaulting to the review package stem.
